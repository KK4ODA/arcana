# D. Application user experience

## Design direction

The UI aims to feel like a technical instrument or reference application:

- **Dense and readable.** 14 px base text, tables for anything that is a
  list, tabular numerals for sizes and dates, monospace only for
  identifiers and figures.
- **Restrained hierarchy.** One accent color (ink blue), 1 px borders, 3 px
  radii. No gradients, shadows (except the sticky selection bar), animated
  decoration, hero sections, or icons that carry no information.
- **Status by meaning.** A small status dot (green ok, amber attention, red
  error, blue info) next to a word. Badges for license class (CC-BY-SA-4.0,
  Non-commercial, Restricted, License unverified) and warnings (Medical,
  Regulatory, Dated).
- **Plain language.** Messages say what happened and what to do ("Queued
  downloads exceed the free space above your reserve. Some downloads will
  pause.").
- **Light and dark themes** follow the system by default and can be
  overridden in Settings. All colors are CSS variables.
- **Fully offline.** System font stack, no web fonts, no CDN, no remote
  images. A test scans the embedded assets for external URLs, and the
  acceptance test runs a browser that fails on any non-local request.
- **Accessible.**
  - A skip link and visible focus rings.
  - Labelled controls and native `<dialog>`, `<table>` and `<select>`
    elements.
  - `aria-current` on navigation and an `aria-live` status area.
  - The progress bars expose values.
  - Every action is reachable by keyboard.
  - Motion only for progress bars, and only when reduced motion is not
    requested.
- **Responsive.** One layout from a 390 px phone to a desktop. Secondary
  table columns hide below 820 px, and the category sidebar stacks above
  results.

Implementation: vanilla ES modules (`internal/web/static/js`), no
framework and no build step. That means no npm supply chain for the shipped
UI. The UI runs under a strict CSP: no inline scripts and no inline style
attributes; styles are set through CSSOM.

## Navigation

```
Arcana  <library label>   Library | Discover | [Maps] | Downloads ³ | Updates ² | Server | Settings      ● Offline ready  ● Sharing
```

- **Maps** appears when Phase 3 ships. It is absent from Phase 1 rather than
  shown as a dead tab.
- Counts on Downloads and Updates show active jobs and available updates.
- **Settings** is hidden for network clients, which have read-only access.

  banner (medical in red). The archive itself loads from the content
  origin. "Open in new tab" gives the full-window archive.

### Entertainment: board games and films

The Entertainment page lists the seven built-in board games, the films on
the drive (with where this browser stopped watching), and, for the
administrator, the films in the catalog with a *Download* button each.
Installed archives in the entertainment category (board-game and film
questions and answers) are listed below. A game page shows the board, whose
turn it is, the computer's level, *Undo*, *New game* and *How to play*;
pieces are chosen and then moved by tapping, and the squares a selected
piece can reach are marked. A film page plays the film with its licence,
source, download check and content notes. See ADR-0027.

### Medicines: labels, situations, home care and herbs

The Medicines page is always in the navigation. With the FDA label
reference installed it has four tabs: *By name*, *By situation*, *Home care
and herbs* and *About the data*; without it, the last three and a line
saying how to get the labels. *By situation* takes up to five of 39
everyday problems and lists, for each, the non-prescription medicines whose
labels name it, then its home care and herbs. A remedy page shows the
cautions first (boxed), then uses, how it is used and what the evidence
shows, the government page it summarizes and the compiler. Every page
carries the medical notice, and the acknowledgement is asked once per
browser. See ADR-0022 and ADR-0028.

- **Filters and sort.** Category, language (defaults to the browser
  language and is remembered), full-text catalog search (FTS5), and sort by
  relevance, title, size or newest first.
- **Detail dialog.**
  - Description, then every warning.
  - Provenance: publisher, source, provider, identifier.
  - Edition: version, publication date, catalog verification date.
  - Languages, coverage, format and exact or estimated size.
  - Content richness and search capability.
  - Integrity source (published SHA-256 / metalink / none).
  - License with notes, and article count.
  - An **Editions** table compares alternatives; choosing one replaces any
    other edition of the same resource in the selection.
- **Selection bar.**
  - Sticky at the bottom: count, download size, and free space after the
    plan with the reserve kept.
  - Turns amber when the plan fits only if estimates hold. Turns red and
    disables Download when it does not fit.
  - Uses the same storage bar as the dashboard. The selection persists in
    the browser.

### Collections and the installation wizard

"Collections and recommendations" opens the wizard dialog:

1. **Goal.** Choose one of the nine presets, from "Family Emergency
   Preparedness" to "Comprehensive Reference Library".
2. **Language.** Choose a language; editions missing in that language fall
   back to English with a note.
3. **Capacity.** Automatic: the budget is the current drive's headroom
   after queued downloads and the reserve. It is shown in the footer.
4. **Review.** A table of every item with priority, chosen edition, size
   and a sentence explaining why. For example: "Chose introductions only,
   no images (14.4 GB). Larger editions do not fit the remaining space:
   full articles with images (127 GB), full articles, no images (52.7 GB)."
   Checkboxes allow removing items or adding skipped ones.
5. **Add to selection.** Nothing downloads until the user presses
   *Download selected*, after seeing the storage bar.

Planned refinements (Phase 2):
- A geography step for regional maps and band plans.
- A "detail level" slider that biases toward text-only or image-rich
  editions.
- Saving custom presets to `user/presets/`.

### Downloads

- One row per job: title, edition (and the version it replaces), state
  (Queued, Locating, Downloading, Waiting to retry with the next attempt
  time, Paused, Verifying, Installing, Installed, Failed with reason,
  Cancelled), progress bar with bytes, speed, ETA and source mirror.
- Actions: Pause, Resume/Retry, Cancel (asks for confirmation; deletes only
  partial data), Clear.
- The view refreshes every 1.5 s while visible.

### Updates

- Last successful catalog check and any provider errors, shown without
  network errors when offline.
- A table of updates: installed edition and date against available edition
  and date, download size and priority (High for medical and regulatory).
- Update selected, or Select all.
- An explanation that the current edition stays usable until the new one
  is verified.

### Server

Shows:
- the local address;
- whether network sharing is on, with its addresses;
- the ports (interface and content);
- read-only rules for network devices;
- how to enable sharing.

The QR code, `arcana.local` and hotspot control arrive in Phase 4 and are
described as planned, not shown as controls.

### Settings

- **Storage:** reserve (default 5 % of the drive, between 1 and 50 GB).
- **Downloads:** simultaneous downloads, bandwidth limit, and whether
  downloads from LAN addresses are allowed.
- **Network sharing** (takes effect at restart).
- **Catalog sources:** Kiwix on/off; add or remove feeds.
- **Theme.**
- **Library integrity:** quick check (presence and sizes) or full check
  (re-hash), with findings explained.
- **About:** location, library ID, version.

Settings are saved atomically to `user/settings.json` on the drive.

### First-run setup

Shown when Arcana starts with no library next to it:

1. A short explanation that everything lives in one folder that can move
   between computers.
2. A path field with the suggested folder (where Arcana.exe sits), a name,
   and **Create library**.
3. A table of detected drives: mount point, label, file system with limits
   (FAT32 max file 4 GiB), formatted capacity and likely advertised size
   ("sold as 1 TB"), free space, removable or internal or system, an
   existing library if present, and file-system warnings (NTFS read-only on
   macOS; exFAT has no journal, so eject safely).
4. Clicking a drive fills in the path.

## Storage-management interface details

- **Two units.** Sizes use decimal units (GB), as drive packaging does. The
  dashboard explains the difference from the operating system's figure,
  e.g. "likely sold as 1 TB; Windows shows 931 GiB".
- **Segments.**
  - Installed (including partial downloads)
  - Other files (not Arcana's)
  - Queued remaining
  - Selected
  - A red overflow segment when over budget
  - The hatched reserve
  - Free space
- **Estimates.** Estimated sizes are prefixed with "≈". The plan reports
  "tight" when the uncertain share of the selection exceeds four times the
  remaining headroom.
- **No silent deletions.** Arcana never deletes or substitutes content to
  make room. Updates need room for both versions until verification, and
  the planner accounts for that.

## Client portal (network devices)

Phones and tablets get the same UI.
- **Settings hidden;** mutating buttons are not shown.
- **Pill:** "Network client (read-only)".
- **Readable** at 390 px; content opens in the reader or a new tab.

In Phase 4 a landing page at `http://arcana.local/` (where mDNS works),
plus an IP address and QR code shown on the host, will help devices
connect.
